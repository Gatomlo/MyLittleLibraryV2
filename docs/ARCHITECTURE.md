# Architecture de MyLittleLibraryV2

Référence détaillée du code (le résumé est dans `CLAUDE.md`, l'usage dans `README.md`, l'interface dans
`public/app/README.md`). À tenir à jour quand l'architecture, les migrations ou le déploiement changent.

## Architecture
- `server.js` : en-têtes de sécurité et compression, fichiers de l'interface (`/_v/<version>/…` gardés en cache, version = empreinte de `public/` : `assetVersion`), routes globales (`/api/auth/*`, `/api/me/*`, `/api/admin/*`), page `index.html` en gabarit (`sendIndex` : `{{ROOT}}`, `{{ASSETS}}`, `{{NONCE}}`, `{{CONFIG}}`), montage `/:slug/…`.
- `lib/util.js` : `httpError`, `str`, `intOrNull`, `asyncHandler`, `csvCell`, `ttlCache`, `limiter`. `lib/net.js` : téléchargement limité aux adresses publiques (`fetchPublic`, `readBody`), `MLL_OFFLINE`. `lib/zip.js` : lecture plafonnée des zip (JSZip pour les epub, yauzl pour les archives). `lib/security.js` : en-têtes et politique de contenu (CSP) des pages.
- `lib/db.js` : bases séparées. **Centrale** `data/central.db` (users, sessions, settings, libraries + réglages, library_slug_history, user_libraries, user_library_prefs) et **une base par bibliothèque** `data/libraries/<id>/library.db` (books, copies, loans, borrowers, categories, tags, statuts, lecteurs, kobo_*), avec `media/`, `ebooks/`, `backups/` dans le même dossier (id stable, pas le slug). La centrale est attachée (`core`) à chaque base de bibliothèque : les requêtes joignent livres et `users`/`libraries` sans préfixe, mais **pas de clé étrangère entre bases** (colonnes `library_id`/`user_id` gardées sans FK ; `removeUserData` nettoie à la suppression d'un compte, `removeLibraryFiles` supprime le dossier). `db.prepare` garde les requêtes préparées par connexion (400 au plus). `db` (façade) suit le contexte `AsyncLocalStorage` : `inLibrary(id, fn)` (posé par le routeur de library-api.js et redonné par `handler()` (lib/library/catalog.js) dans les routes, kobo et stats, car `express.raw` perd le contexte), sinon centrale (une table de livres y est introuvable). Migrations : `CENTRAL_MIGRATIONS` (v7) / `LIBRARY_MIGRATIONS` (v6), `PRAGMA user_version`, SQL ou fonction). Ancienne base unique `data/library.db` : `lib/legacy-migrations.js` (v1-v19, ne plus modifier) puis `separateLegacy()` au démarrage (sauvegarde `data/backups/library-avant-separation-*.db`, préparation dans `data/.separation`, `central.db` créé en dernier). `media.*` et `ebooks.*` prennent l'id de la bibliothèque en premier argument. `bookSearchText`, `nextCopyCode`, `slugify`.
- `lib/library-api.js` : assemble l'API d'une bibliothèque (`/:slug/api/...`) : public (catalogue, fiche), puis les gardes : compte de la bibliothèque `isMember` ; lecteur limité à `READER_GET` / `READER_WRITE` (liste blanche), `/stats`, `/kobo` sauf création de fiche, et `fullBook` sans emprunteurs ni historique ; réglages : middleware `config` (`canConfigure`) posé **sur chaque route** concernée (`/settings` en écriture sauf `{labelLayout}` seul, `/settings/logo`, `/values/*` en écriture, `/empty`, `/copies/renumber`) — ne jamais le remplacer par un test sur le chemin (Express ignore la casse et le `/` final).
- `lib/library/` : `catalog.js` (lecture : `searchBooks`, `bookDetail`, `listLoans`, classement, réglages publics, `handler`, `findLibrary`), `fiches.js` (écriture : champs d'un livre, statuts, catégories et tags, couvertures, exemplaires, `updateFromImport`), puis un fichier de routes par domaine : `routes-public.js`, `routes-settings.js`, `routes-terms.js`, `routes-books.js` (livres, actions en masse, vidage), `routes-copies.js`, `routes-loans.js` (emprunteurs, prêts, réservations), `routes-labels.js`, `routes-import-export.js`. Chacun exporte `register(api, gardes)`.
- PWA : `public/sw.js` (service worker sans cache, page hors connexion), manifeste dynamique par bibliothèque (`/:slug/manifest.webmanifest`, `sendManifest` dans server.js), icônes PNG dans `public/` (régénérer depuis `icon.svg` / `icon-maskable.svg` si le logo change).
- `lib/wishes.js` : souhaits (centrale v4 : `wishes` par compte, `wish_shares` owner → viewer ; v8 : `wishes.library_id`, souhaits propres à une bibliothèque, existants rattachés à la première bibliothèque du compte), routes globales `/api/wishes` avec bibliothèque obligatoire (`?library=` ou corps `library`, compte membre : `pageLibrary`, sinon 400 ; page racine `#/wishes` : invite à ouvrir une bibliothèque) (`owners`, liste `?owners=1,2&library`, `lookup/:isbn`, `search?q`, `shares`, `export.xlsx|csv`). Visibles (dans la bibliothèque) : soi, les comptes membres qui partagent avec soi, et si `canManage` : comptes liés (`user_libraries`, front : liste déroulante `combo` au lieu des pastilles). Couvertures : `findCover` (`searchCovers` de covers.js, résultats `loose` écartés) dans `lookup`, `GET /wishes/cover?isbn&title&authors` et en arrière-plan à l'affichage (`fillCovers` ; `cover_url` NULL = jamais cherchée, '' = introuvable). Image choisie ou photographiée : `coverData` → fichier dans `data/wishes/`, `cover_url = 'file:<nom>'`, servie sur `/api/wishes/image/<nom>` (`coverOut`, front `wishSrc`), supprimée avec le souhait (`dropFile`, `purgeFiles` au démarrage) ; `GET /wishes/covers` alimente `openCoverSearch` ; à l'ajout au catalogue, l'image enregistrée est relue par le navigateur et envoyée avec la fiche. Seul le propriétaire modifie ou supprime. Pas d'état « acquis » (v6 : supprimés ; colonnes `status`/`acquired_*` d'une première v4 ignorées) : `POST /wishes/:id/added {library, bookId}` (propriétaire ou gestionnaire qui le voit, livre de cette bibliothèque) retire le souhait. Front : `#/wishes` (bibliothèque et racine), `pendingWish` pré-remplit Ajouter puis appelle `added`. `CONFIG.library.id` est fourni par `renderIndex`.
- Réservations et disponibilité : `COPY_COUNTS.reservation_count` ; `availableCopies` = libres non réservés, `reservedCopies` = libres mis de côté ; `markReserved` attribue les exemplaires libres aux réservations dans l'ordre (`reservedFor` en gestion, `reserved` en public) ; filtre « Disponibles » = `FREE_COPIES`.
- Accueil (`lib/home.js`, monté avant la garde « gestion ») : `GET /home` = cartes du compte (`CARDS`, disponibilité selon `member` / `manage` et options) + données des cartes affichées ; `PUT /home/cards {order, hidden}` (`order: null` = défaut) dans `user_library_prefs.home_cards` (centrale v5, repris par les archives). Personnalisation : menu du compte (`openHomeCustomize`). Nouvelles cartes : `series`, `toread`, `rate` (PUT status avec `reading: 'read'` + avis, sinon le statut serait effacé), `idea` (`pickIdea`, `GET /home/idea?exclude=`), `topwishes` (config ; groupes ISBN/titre, `pendingWish` avec `ids`/`owners` : tous les souhaits retirés, tous lecteurs), `activity`, `kobo`. Tuiles : mode `compact` (< 104 px) et lignes entières (`fitHome`). Carte « À faire » : fiches incomplètes = sans couverture, résumé, ISBN ou catégorie (`HOME_MISSING`). Carte « Pour moi » : livres ajoutés depuis 30 jours dont on est lecteur + lecteur d'un livre rendu depuis 14 jours. Front `viewDashboard` (`#/home`, arrivée après connexion et au premier affichage connecté ; `#/` reste le catalogue) : cartes (`.home-cards`) en grand écran, tuiles (`.home-tiles`) sous `HOME_PHONE_QUERY` ; `fitHome` : une seule colonne, `HOME_PHONE_TILES` (6) tuiles puis « Voir tout » (`#home-more`, choix gardé en `localStorage` `mll-home-all`), hauteur réglée sur l'écran ; `body.home-fit` coupe le défilement seulement si tout tient (68 px min. par tuile, sinon la page défile). Rangées de livres : une ligne, les suivantes masquées (`grid-auto-rows: 0`). `loansTabNext` ouvre un onglet des Prêts, `openCatalog(patch)` un filtre du catalogue.
- Rappels de retour : centrale v4 `libraries.reminder_mode` (manual | auto), `reminder_offset` (jours depuis `due_at`, négatif = avant), `reminder_subject/body` (vide = modèle `REMINDER_DEFAULT` du front) ; bibliothèque v4 `loans.reminded_at`, `reminder_count`. `toRemindSql` (lib/library/catalog.js) : échéance + offset atteinte et pas relancé depuis, puis tous les 7 jours en retard. `GET /loans?status=remind`, `POST /loans/reminded {ids}`, `summary.toRemind/reminder`. Front : `sendReminder` (mailto puis confirmation), `loanCache`, onglet « À relancer » groupé par emprunteur.
- Accessibilité (public/app/utilitaires.js, routage.js) : gestion globale des `.modal-backdrop` (observateur : focus, Échap → `[data-close]`, Tab contenu, focus rendu), `announcePage` après chaque route (titre, focus sur `#view`), `aria-current` dans la nav, classe `.sr-only`, lien d'évitement intercepté (routes en #).
- `lib/stats.js` (stats, confidentialité : `share_stats` 0 personne, 1 tous les membres, 2 comptes de `stats_shares` (centrale v10, repris par les archives : `share_with`), `sharingMembers(lib, viewer)` ; page Statistiques : Mes statistiques, Bibliothèque, puis membres qui partagent dans une liste `combo` ; réglages personnels `PUT /stats/prefs` (centrale v9 : objectifs `GOALS` en JSON dans `user_library_prefs.reading_goals`, `{goals: {pages: 3000, series: null}}` modifie seulement les clés fournies ; avancement `goalProgress`, utilisé par les statistiques et la carte `goal` de l'accueil) affichés dans « Mon compte » : `prefsHtml` / `bindPrefs`, bibliothèque ouverte avec statistiques), `lib/auth.js` (scrypt, sessions ; `users.role` = `admin` | `user` (compte ordinaire) ; rôle **par bibliothèque** (centrale v7) `user_libraries.role` = `manager` (gestionnaire) / `librarian` (bibliothécaire) / `user` (lecteur, lecture seule) : `roleIn(user, lib)`, `isMember` = compte lié ou admin, `canManage` = membre sauf lecteur (catalogue, prêts, étiquettes, souhaits des membres), `canConfigure` = admin ou gestionnaire (réglages, classement, vidage, codes) ; `spreadRoles` (db.js, à chaque démarrage) reporte un ancien rôle de compte sur ses liens ; `librariesOf` donne le rôle, front `libRole()` et mêmes fonctions, routes `member` / `manage` / `config`, libellés `ROLE_LABELS` / `ROLE_HELP` ; API comptes : `libraries: [{id, role}]`), `lib/invitations.js` (centrale v7 `invitations` : jeton en clair, bibliothèque, rôle, expiration ; `/api/admin/invitations`, et sans connexion `GET|POST /api/invitations/:token` = création du compte ou ajout de la bibliothèque au compte connecté, rôle existant jamais modifié ; front `#/invite/<jeton>` sur l'adresse de la bibliothèque), `lib/isbn.js` (Google Books / BnF SRU / Open Library ; `findIsbn` = ISBN unique par titre + auteur (BnF), `searchEditions` = liste d'éditions pour `GET /isbn-search?title&author|q&bookId` (+ ISBN du fichier epub) ; résumés FR en dernier recours via leslibraires.fr, 1 requête / 3 s — placedeslibraires.fr et Decitre bloquent l'hébergeur), `lib/covers.js` (recherche de couvertures), `lib/media.js`.
- Cookie de session (`setSessionCookie`, auth.js) : en HTTPS `SameSite=None; Secure; Partitioned` pour fonctionner dans un cadre d'un autre site (onglet « Site web » de Teams), `Lax` en HTTP ; l'ancien cookie non partitionné est effacé, `sessionTokens` accepte les deux. CSRF : `jsonOnly`. Connexion : `verifyPasswordAsync` (même calcul si le compte n'existe pas), blocage par identifiant (8 échecs / 15 min) et réponses ralenties si les échecs s'accumulent globalement (`failureDelay`) ; `revokeSessions` ferme les autres sessions au changement de mot de passe ; `signupAllowed` limite les comptes créés par lien d'invitation (20 / heure).
- Archives par bibliothèque (`lib/archives.js`, Administration › Sauvegarde) : `GET /api/admin/libraries/:id/archive?db=1&ebooks=1&covers=1` → `mylittlelibrary-<nom>.zip` (`library.db`, `ebooks/`, `media/`, `manifest.json` : réglages de `libraries`, membres, prefs, comptes cités id → identifiant). Restauration en deux temps : `POST /api/admin/archives` (zip brut, 1 Go, exception `jsonOnly` ; enregistré sur disque puis lu entrée par entrée avec yauzl, extrait dans `data/.restore-*` avant renommage) → jeton + bibliothèque du même nom (casse ignorée), puis `POST /api/admin/archives/:token/apply {overwrite}` (remplace seulement les éléments présents, copie de sécurité de la base, `library_id` réécrit, comptes remappés par identifiant sinon retirés). Rappel mensuel : `backupReminder` de `/api/auth/status` (réglages `backupDoneMonth` / `backupSkippedMonth`), « Reporter » = `sessionStorage` `mll-backup-snooze` (effacé à la connexion).
- Réglages globaux : table `settings` (clé/valeur, `getSetting`/`setSetting` dans db.js). Clé Google Books : `googleBooksKey()` = réglage `googleBooksApiKey` (Administration › Google Books), sinon `GOOGLE_BOOKS_API_KEY`.
- Interface : palette et composants dans `style.css` (variables `:root`, teintes `--sun/--coral/--sky/--grape/--rose` + `-soft`), police Nunito hébergée (`public/fonts/`, déclarée en tête de `style.css`). Textes d'aide : jamais de paragraphe explicatif, utiliser `hint(texte)` (icône « ? » + info-bulle, `public/app/utilitaires.js`) et des libellés courts. Smartphone : pas de long libellé sur un bouton, `iconText(icone, texte)` = icône seule sous 760 px (avec `title` / `aria-label`), classes `hide-mobile` / `.btn-row.only-mobile`, ou libellé court : `<span class="hide-mobile">long</span><span class="show-mobile">court</span>`. Icones SVG inline : `public/app/icones.js` (`icon(nom)`, `PAGE_COLORS`, `decorateTitle` ajoute la pastille des h1 selon l'adresse).
- `public/app/*.js` : SPA en modules ES natifs (routes en hash), un module par domaine, point d'entrée `main.js` ; règles (chaîne d'imports qui fixe l'ordre d'exécution, objet `pending`, pas de gestionnaire en ligne) dans `public/app/README.md`. `public/vendor/` : bibliothèques du navigateur copiées des paquets npm (scanner, import Excel, liseuse epub). `public/embed.js` : widget catalogue WordPress (Shadow DOM). `wordpress/…/mylittlelibrary-catalogue.php` : plugin shortcode `[bibliotheque …]`.
- `data/` (non versionné) : `central.db`, `libraries/<id>/{library.db, media/, ebooks/, backups/}`, `wishes/` (images des souhaits), `backups/`. Images servies sur `/<slug>/media/` (plus de `/media` global ; `libraryInfo.logoUrl` = `<slug>/media/…`). Sauvegarde admin = zip des bases (`backupTo`).

## Modèle (points non évidents)
- Multi-bibliothèques : tout est filtré par `library_id` ; URL de bibliothèque = slug fixé à la création.
- `copies.format` = `physical` | `ebook` : l'exemplaire numérique n'a **pas de code, d'étiquette ni de prêt** (un seul par livre). `books.format` n'est plus utilisé.
- Fichier epub (v16, `lib/ebooks.js`) : sur l'exemplaire numérique, `file_key` (fichier dans `data/libraries/<id>/ebooks/`, jamais servi en statique ; métadonnées lues avec un plafond de décompression, `lib/zip.js`), `file_name`, `file_size`. Droits **par bibliothèque** (v17) `libraries.ebook_visible` / `ebook_read` / `ebook_download` = `public` | `members` (`isMember`, lecteurs compris) | `managers` (`canManage`) | `admin` (lire ou télécharger rend visible ; `ebooks.rights(lib, user)`) ; les colonnes `copies.file_visible/read/download` ne servent plus. Import de plusieurs epub : `POST /import/epub` (brut, une requête par fichier ; `lib/epub-meta.js` lit titre, auteurs, résumé, ISBN (OPF, sinon texte du début et de la fin du livre, ISBN papier préféré : `isbnFromText`, `readEpubIsbn`), série, couverture ; fiche existante = même ISBN ou même titre + auteur → fichier ajouté s'il manque). Envoi brut `PUT /copies/:id/file` (application/epub+zip, en-tête `X-File-Name`, 100 Mo, exceptions dans `jsonOnly` de server.js avec `/import/epub` et `/kobo/scan`) ; accès `GET /public/books/:id/epub[?download=1]` ; `book.ebookFile` = droits du visiteur. Liseuse `#/read/:id` (epub.js + JSZip servis sur `/vendor/`). Fichiers orphelins supprimés par `ebooks.purgeOrphans(libId)` après chaque suppression.
- Livre : `collection` (éditeur) distincte de `series` + `series_number` (tome). `collection_number` n'est plus utilisé.
- Statuts de lecture par compte (`book_user_status`) : to_read / reading / read / abandoned + liked / disliked + `rating` (1-5, v19 ; conservée si absente du PUT), avec dates. Filtre catalogue `rating=n` (n étoiles et plus) | `none`.
- Lecteurs (`book_readers`, v15) : comptes membres liés à un livre, indépendants du statut (jamais retirés par un changement de statut). Fiche : bouton « Intéressé » (soi-même, `POST/DELETE /books/:id/readers`) ; autres membres via le formulaire « Modifier » (`readers` de `PUT /books/:id` remplace la liste). Filtres catalogue `mine` (Mes livres) et `reader`. Ajout d'un livre et import : le créateur par défaut, ou `readers` (identifiants, ou noms séparés par des virgules pour la colonne « Lecteurs »). En mise à jour par import, seule la colonne compte. Membres : `libraryMembers` (lib/library/catalog.js). Les emprunteurs sont des personnes extérieures sans compte.
- Tags = vrais tags (thèmes libres). En v15, les tags qui portaient le nom d'un compte ont été convertis en lecteurs.
- Fiches incomplètes : `MISSING` (lib/library/catalog.js, conditions SQL par champ) → `GET /books/missing` (comptes), filtre `missing=` de `/books` et de `/export/inventory.*`.
- Prêts : `loans.due_at` ('YYYY-MM-DD', bibliothèque v2 ; défaut `libraries.loan_days`, centrale v3, 0 = aucune ; `dueDate()`, retard = `OVERDUE` en SQL, `GET /loans/summary`, `PUT /loans/:id {dueAt}`). Réservations (`reservations`, bibliothèque v3 : au nom d'un emprunteur `borrower_id`, `created_by` = compte qui l'a saisie ; `resolveBorrower` commun avec le prêt, qui retire la réservation de l'emprunteur ; `reservationsFor` dans `bookDetail` et la réponse du retour). Front : `openCopy` (retour express si prêté), `returnLoan` (alerte réservation), `loanFor` (emprunteur choisi depuis sa fiche, oublié en quittant `/c/` et sa fiche), `pendingAddIsbn`, `refreshLoanBadge`.
- Import `onDuplicate` : `copy` | `skip` | `new` | `update` (`updateFromImport` : colonnes non vides écrasent la fiche, repérée par `bookId` = colonne « ID fiche » de l'export, sinon ISBN).
- Auteurs, séries, éditeurs, collections : pas de table, valeurs libres des fiches (auteurs séparés par des virgules). Gestion via `/values/:kind` (`VALUE_FIELDS`, `rewriteValues`, casse ignorée) ; front : `categoryManager` (`TERM_KINDS`, `free`), onglets « Classement » des réglages.
- Liseuses Kobo (v17, `lib/kobo.js`, option `enable_kobo`, exige `enable_ebooks`) : le navigateur lit la Kobo branchée (Chrome : `showDirectoryPicker` en lecture/écriture ; Firefox : `webkitdirectory`, lecture seule + avertissement) et envoie `.kobo/KoboReader.sqlite` brut à `POST /kobo/scan` (en-tête `X-Kobo-Version` = `.kobo/version` ; journal `-wal` non vide ajouté à la suite, taille dans `X-Kobo-Wal-Size`, sinon la base peut être illisible seule ; `X-Kobo-Db-Size` = taille attendue, envoi tronqué = 400 ; base en partie abîmée (fréquent, la liseuse fonctionne) : relue `NOT INDEXED`, sinon jusqu'à la partie abîmée (`partial` : pas de retrait des livres non lus, pas d'écriture, `warning`) ; base illisible = 400 avec conseil), lu par `node:sqlite` (livres `ContentType = 6`, `file://` seulement). Modifier une liseuse ou ses livres (renommer, supprimer, rattacher, nouveau scan) : son propriétaire ou un compte `canManage` (`mayChange`) ; changer le propriétaire : `canManage` seulement. Tables `kobo_devices` (numéro de série, propriétaire `user_id`) et `kobo_items` (livres du dernier scan ; `book_id`, `manual` = rattachement manuel conservé, `last_derived` = statut déduit au scan précédent, appliqué seulement s'il change, jamais de rétrogradation d'un « Lu » ; abandonné = progression inchangée depuis `user_library_prefs.stale_days` et au moins 5 % lus, sinon ignoré comme ouvert par erreur). Rapprochement : repère `[mll-<id>]` dans le chemin, ISBN, titre + nom de l'auteur. Envoi : `GET /kobo/books/:id/epub` (droit de téléchargement) réécrit l'OPF d'après la fiche (`rewriteOpf` : titre, sous-titre (EPUB 3), auteurs, éditeur, année, résumé, catégories en `dc:subject`, ISBN, `calibre:series` + EPUB 3 `belongs-to-collection` ; anciennes valeurs, contributeurs, identifiants et `calibre:*` retirés, champ vide = retiré ; gardés : langue, identifiant unique (ISBN remplacé), `dcterms:modified`, couverture, `rendition:*`), met la couverture de la fiche (`setCover` : image de couverture remplacée, sinon `mll-cover.*` ajoutée, `<meta name="cover">`) et donne le chemin rangé comme Calibre `<Nom, Prénom>/<Titre> - <Auteurs> [mll-id.<empreinte>].epub` (ASCII, à la racine ; série seulement dans les métadonnées ; anciens envois dans `Bibliotheque/` laissés en place) (en-tête `X-Kobo-Path` ; `koboStamp` = empreinte des champs écrits, de la couverture et du fichier, `KOBO_FORMAT`). La liseuse ne relit jamais un livre déjà importé : une fiche modifiée donne un autre nom, `kobo_items` porte `outdated` (chemin ≠ `koboPath`) et un nouvel envoi (fiche, sélection, « Mettre à jour N livres » de la page de la liseuse) copie la nouvelle version puis supprime l'ancien fichier (Chrome). La base de la liseuse n'étant jamais modifiée, le nouveau fichier y repart de zéro (progression, marque-pages, « Lu ») : un livre commencé ou lu (`started`) est exclu des envois groupés et de « Mettre à jour N livres » (badge « Fiche modifiée »), l'envoi depuis la fiche demande confirmation. **Écriture dans la base de la liseuse** (option par liseuse `kobo_devices.write_db`, v5 ; `lib/kobo-db.js`, comme Calibre ; Chrome seulement) : le navigateur ajoute `X-Kobo-Write: 1` au scan si l'option est active ; journal `-wal` non vide envoyé : la base complète (journal reporté, `wal_checkpoint(TRUNCATE)` sur la copie) est toujours réécrite et le journal supprimé, comme Calibre (`dbUpdate.merged` ; arrêt en cours sans risque, la liseuse rejouerait le même journal) ; copie de la liseuse avec son journal (`.mll-backup-wal`) ; après le scan, le serveur applique à une copie de la base les valeurs des fiches (`koboValues` : Title, Subtitle, Attribution, Description en HTML, Publisher, ISBN, Series, SeriesNumber(Float), SeriesID = celui d'un livre de la boutique de même série, sinon le nom ; colonnes absentes ignorées, lignes `ContentType = 6` en `file://` seulement, `quick_check` avant et après, schéma jamais modifié), la base saine (`quick_check`, journal reporté) de **chaque scan**, option ou non, est gardée dans `data/libraries/<id>/kobo-backups/<liseuse>-<date>-<empreinte>.sqlite.gz` (gzip, une fois par contenu, 10 dernières par liseuse ; `GET /kobo/devices/:id/backups[/:name]`, décompressée à l'envoi ; anciennes `.sqlite` lues) et renvoie `dbUpdate {token, changed, covers}`. Le navigateur copie la base actuelle en `.kobo/KoboReader.sqlite.mll-backup`, récupère la base modifiée (`GET /kobo/devices/:id/db/:token`, 30 min), la remplace (`createWritable` : l'originale reste intacte si l'écriture échoue), supprime `-wal`/`-shm`, efface les vignettes des fichiers remplacés (`kobo_items.cover_refresh`, posé par `/pushed` sur une ligne déjà importée ; dossier `.kobo-images/<n1>/<n2>` = `qhash(ImageId)` de Calibre), puis `POST /kobo/devices/:id/db/applied`. Avec l'option, un envoi d'un livre déjà importé remplace le fichier sous le même nom (progression gardée) puis rescanne ; `outdated` compare l'empreinte envoyée (`kobo_items.sent_stamp`, sinon celle du nom) à `koboStamp`. Toujours avec l'option : **livre retiré** (fichier effacé par le navigateur) marqué `kobo_items.removed` (v6, `POST /kobo/items/:id/removed`, masqué partout) puis supprimé de la base au scan suivant comme Calibre (`removeBooks` : ligne du livre, chapitres `BookID`, `volume_shortcovers`, `ShelfContent`, `content_settings` ; surlignages gardés) ; **collections** Kobo d'après les fiches (`kobo_devices.collections` = both | categories | tags | none ; `syncShelves` : `Shelf` Id = nom comme Calibre, `ShelfContent`, collections de l'appli dans `kobo_shelves` (retenues à `/db/applied`), seules elles sont retirées d'un livre, vides = `_IsDeleted`). **Surlignages et notes** (table `Bookmark`, livres `file://`) relevés à chaque scan dans `kobo_annotations` (v6), affichés sur la fiche pour le propriétaire de la liseuse (`GET /kobo/books/:id/annotations`, « Mes surlignages »). **Kepub** (option `kobo_devices.kepub`, par défaut) : `GET /kobo/books/:id/epub?format=kepub` convertit les documents (`lib/kepub.js`, comme kepubify : phrases et images en `<span class="koboSpan" id="kobo.P.S">`, corps dans `div#book-columns > div#book-inner`, documents déjà convertis ou atypiques laissés tels quels) et donne l'extension `.kepub.epub`. Restauration (page de la liseuse, « Sauvegardes de la base ») : une sauvegarde de l'appli ou la copie de la liseuse, après copie de la base actuelle en `.mll-before-restore`. Envoi depuis l'appli (Chrome) : `POST /kobo/devices/:id/pushed` crée une ligne `pending` (v18) gardée jusqu'à ce qu'un scan retrouve le livre (30 jours max). Front : liseuse branchée = variable `kobo` (session de la page ; `kobo.device` après scan ; `koboOn()`), branchement par le menu du compte (« Brancher une liseuse », « Toutes les liseuses », « Paramètres de <liseuse> » = `editKoboDialog` de la liseuse de la page ouverte, sinon de celle branchée, si modifiable : `koboSettingsTarget`, aussi sur téléphone) ; Chrome : dossier mémorisé en IndexedDB (`mll-kobo`, par bibliothèque), reconnexion seule si l'autorisation est gardée sinon « Reconnecter » (un clic), pas de vérification en continu (un accès répété laissait Windows servir ensuite une copie périmée de la base de la liseuse, même après éjection, d'où des bases réécrites en retard et abîmées) : présence vérifiée au début de chaque action (`ensureKobo`, sinon `markUnplugged`) ; ouverture de la page avec une liseuse déjà autorisée et branchée : scan automatique (`koboRestore`, au plus une fois toutes les 2 min, `sessionStorage` `mll-kobo-autoscan`) ; « Terminer » (page de la liseuse, menu du compte ; `ejectKobo`) écrit d'abord en une fois les changements faits depuis le dernier scan (livres retirés ou remplacés, `koboChanged` : plus de scan après chaque action), puis recharge la page sans toucher à la liseuse (`mll-kobo-ejected`, comme un onglet fermé) jusqu'à la prochaine reconnexion ; base peut-être périmée au scan (livres `pending` envoyés il y a plus de 2 min toujours absents : `pendingOld`, `stale`) : pas d'écriture, le navigateur relit la base une fois (`X-Kobo-Retry`, écriture alors permise) puis signale les livres pas encore importés ; nom par défaut « <modèle> de <compte Kobo> » (`MODELS`, table `user`.UserDisplayName tronqué avant le @, souvent une adresse e-mail), remplace seulement un nom par défaut ; page d'une liseuse filtrable comme le catalogue (`GET /kobo/devices/:id?q&category&series&tag&reading&sort`, recherche seule sur sa ligne en grand écran : classe `filters-search-row`, filtres de fiche via `searchBooks`) ; seulement si branchée : onglet de la liseuse, filtre catalogue `kobo=on|off&koboDevice=` (searchBooks), envoi groupé depuis la sélection (`pushManyToKobo` ; seule action de la sélection pour un lecteur), « Copier les fichiers manquants » sur la page d'une liseuse, « Supprimer de la liseuse » (Chrome : `kobo.remove` efface le fichier et le dossier parent vide, puis `DELETE /kobo/items/:id`), fiche créée depuis une liseuse ouverte avec retour (`koboReturn`).
- Options par bibliothèque : `enable_ebooks`, `enable_kobo`, `enable_reading_status`, `enable_tags`, `enable_stats`, filtres et éléments des miniatures du catalogue (`catalog_filters`, `catalog_card` : JSON, NULL = tous ; statuts en trois filtres `statusUser`/`reading`/`opinion` depuis v15), bouton Scanner de l'en-tête (centrale v2 : `scan_codes` = copy | isbn | both, `scan_action` = loan | book ; `settings.scan`, front `scanAndOpen`, `GET /copies/by-isbn/:isbn` = livres de l'ISBN + exemplaires papier). `POST /labels/reset` : toutes les etiquettes papier remises en attente (`label_printed_at = NULL`, codes inchanges ; `POST /labels` plafonne a 500 par impression). Transfert d'exemplaire : `POST /copies/:id/move {bookId}` (code, prets et fichier suivent ; 409 si meme fiche ou si la cible a deja un numerique ; renvoie `sourceCopies` pour proposer la suppression de la fiche videe).

## Sécurité (points à ne pas défaire)
- Droits : toute nouvelle route de gestion passe derrière les gardes de `lib/library-api.js` ; une route réservée aux gestionnaires reçoit le middleware `config` ; une route ouverte aux lecteurs s'ajoute à `READER_GET` / `READER_WRITE`. `tests/droits.test.js` décrit la matrice : y ajouter la route.
- Adresse fournie par un utilisateur et appelée par le serveur : toujours `fetchPublic` + `readBody` (lib/net.js), jamais `fetch` directement.
- Fichier zip reçu : `readEntry` / `readText` (plafond) pour JSZip, `eachEntry` (yauzl) pour un fichier sur disque ; jamais `file.async()` sans limite ni `fs.readFileSync` d'une archive.
- Page HTML : envoyée par `sendIndex` (CSP avec nonce, `lib/security.js`). Pas de script ni de gestionnaire en ligne dans l'interface ; nouvelle source externe (image, police, script) = directive CSP à ajuster. Cadres autorisés : `MLL_FRAME_ANCESTORS` (Teams par défaut).
- Valeur insérée dans un gabarit : par fonction de remplacement (`$&`, `$'` dans un nom ne doivent pas être interprétés).
- Export CSV : `csvCell` (lib/util.js) neutralise les formules ; l'import retire l'apostrophe (`cellText`, public/app/import.js).
