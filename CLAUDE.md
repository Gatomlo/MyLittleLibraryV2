# MyLittleLibraryV2

Gestion de bibliothèques (catalogue, prêts, étiquettes QR, import/export, stats) — Node.js ≥ 22.5 + SQLite (`node:sqlite`), Express 4, front SPA sans framework ni build.
Utilisateur francophone : interface, commentaires et réponses **en français**. Commentaires de code sans accents (style existant).

## Déploiement / passerelle
- Montée dans `C:\Users\thoma\ClaudeIA\node-gateway` : jonction `apps/mylittlelibrary` → ce dossier, servie sur `http://localhost:3000/mylittlelibrary/`. Prod : Infomaniak (même passerelle).
- `server.js` exporte `app` ; `app.listen` seulement si lancé directement (`PORT`, défaut 3000).
- Redémarrer la passerelle locale : tuer le process sur le port 3000 (TaskStop ne suffit pas toujours), puis `npm start` dans node-gateway.
- Déploiement : envoyer `lib/`, `public/` (et `server.js`, `package.json` si modifiés, puis `npm install`), **jamais `data/`**, puis redémarrer Node. Les migrations s'appliquent seules au démarrage.

## Architecture
- `server.js` : routes globales (`/api/auth/*`, `/api/me/*`, `/api/admin/*`), page `index.html` en gabarit (`{{ROOT}}`, `{{CONFIG}}`, `{{VERSION}}` = cache-busting), vendors (scanner, excel), montage `/:slug/…`.
- `lib/db.js` : bases séparées. **Centrale** `data/central.db` (users, sessions, settings, libraries + réglages, library_slug_history, user_libraries, user_library_prefs) et **une base par bibliothèque** `data/libraries/<id>/library.db` (books, copies, loans, borrowers, categories, tags, statuts, lecteurs, kobo_*), avec `media/`, `ebooks/`, `backups/` dans le même dossier (id stable, pas le slug). La centrale est attachée (`core`) à chaque base de bibliothèque : les requêtes joignent livres et `users`/`libraries` sans préfixe, mais **pas de clé étrangère entre bases** (colonnes `library_id`/`user_id` gardées sans FK ; `removeUserData` nettoie à la suppression d'un compte, `removeLibraryFiles` supprime le dossier). `db` (façade) suit le contexte `AsyncLocalStorage` : `inLibrary(id, fn)` (posé par le routeur de library-api.js et redonné par `h()` dans library-api/kobo/stats, car `express.raw` perd le contexte), sinon centrale (une table de livres y est introuvable). Migrations : `CENTRAL_MIGRATIONS` (v7) / `LIBRARY_MIGRATIONS` (v4), `PRAGMA user_version`, SQL ou fonction). Ancienne base unique `data/library.db` : `lib/legacy-migrations.js` (v1-v19, ne plus modifier) puis `separateLegacy()` au démarrage (sauvegarde `data/backups/library-avant-separation-*.db`, préparation dans `data/.separation`, `central.db` créé en dernier). `media.*` et `ebooks.*` prennent l'id de la bibliothèque en premier argument. `bookSearchText`, `nextCopyCode`, `slugify`.
- `lib/library-api.js` : API d'une bibliothèque (`/:slug/api/...`) : public (catalogue, fiche), puis trois gardes (compte de la bibliothèque `isMember` ; lecteur limité à `READER_GET` / `READER_WRITE`, `/stats`, `/kobo` sauf création de fiche, et `fullBook` sans emprunteurs ni historique ; réglages `canConfigure`, sauf `PUT /settings {labelLayout}` seul) ; livres, exemplaires, prêts, emprunteurs, étiquettes, import, export, suppression en masse, vidage.
- PWA : `public/sw.js` (service worker sans cache, page hors connexion), manifeste dynamique par bibliothèque (`/:slug/manifest.webmanifest`, `sendManifest` dans server.js), icônes PNG dans `public/` (régénérer depuis `icon.svg` / `icon-maskable.svg` si le logo change).
- `lib/wishes.js` : souhaits (centrale v4 : `wishes` par compte, `wish_shares` owner → viewer), routes globales `/api/wishes` (`owners`, liste `?owners=1,2&library`, `lookup/:isbn`, `search?q`, `shares`, `export.xlsx|csv`). Visibles : soi, les comptes qui partagent avec soi, et avec `library=<id>` si `canManage` : comptes liés (`user_libraries`, front : liste déroulante `combo` au lieu des pastilles). Couvertures : `findCover` (`searchCovers` de covers.js, résultats `loose` écartés) dans `lookup`, `GET /wishes/cover?isbn&title&authors` et en arrière-plan à l'affichage (`fillCovers` ; `cover_url` NULL = jamais cherchée, '' = introuvable). Image choisie ou photographiée : `coverData` → fichier dans `data/wishes/`, `cover_url = 'file:<nom>'`, servie sur `/api/wishes/image/<nom>` (`coverOut`, front `wishSrc`), supprimée avec le souhait (`dropFile`, `purgeFiles` au démarrage) ; `GET /wishes/covers` alimente `openCoverSearch` ; à l'ajout au catalogue, l'image enregistrée est relue par le navigateur et envoyée avec la fiche. Seul le propriétaire modifie ou supprime. Pas d'état « acquis » (v6 : supprimés ; colonnes `status`/`acquired_*` d'une première v4 ignorées) : `POST /wishes/:id/added {library, bookId}` (propriétaire ou gestionnaire qui le voit, livre de cette bibliothèque) retire le souhait. Front : `#/wishes` (bibliothèque et racine), `pendingWish` pré-remplit Ajouter puis appelle `added`. `CONFIG.library.id` est fourni par `renderIndex`.
- Réservations et disponibilité : `COPY_COUNTS.reservation_count` ; `availableCopies` = libres non réservés, `reservedCopies` = libres mis de côté ; `markReserved` attribue les exemplaires libres aux réservations dans l'ordre (`reservedFor` en gestion, `reserved` en public) ; filtre « Disponibles » = `FREE_COPIES`.
- Accueil (`lib/home.js`, monté avant la garde « gestion ») : `GET /home` = cartes du compte (`CARDS`, disponibilité selon `member` / `manage` et options) + données des cartes affichées ; `PUT /home/cards {order, hidden}` (`order: null` = défaut) dans `user_library_prefs.home_cards` (centrale v5, repris par les archives). Personnalisation : menu du compte (`openHomeCustomize`). Nouvelles cartes : `series`, `toread`, `rate` (PUT status avec `reading: 'read'` + avis, sinon le statut serait effacé), `idea` (`pickIdea`, `GET /home/idea?exclude=`), `topwishes` (config ; groupes ISBN/titre, `pendingWish` avec `ids`/`owners` : tous les souhaits retirés, tous lecteurs), `activity`, `kobo`. Tuiles : mode `compact` (< 104 px) et lignes entières (`fitHome`). Carte « À faire » : fiches incomplètes = sans couverture, résumé, ISBN ou catégorie (`HOME_MISSING`). Carte « Pour moi » : livres ajoutés depuis 30 jours dont on est lecteur + lecteur d'un livre rendu depuis 14 jours. Front `viewDashboard` (`#/home`, arrivée après connexion et au premier affichage connecté ; `#/` reste le catalogue) : cartes (`.home-cards`) en grand écran, tuiles (`.home-tiles`) sous `HOME_PHONE_QUERY` ; `fitHome` : une seule colonne, `HOME_PHONE_TILES` (6) tuiles puis « Voir tout » (`#home-more`, choix gardé en `localStorage` `mll-home-all`), hauteur réglée sur l'écran ; `body.home-fit` coupe le défilement seulement si tout tient (68 px min. par tuile, sinon la page défile). Rangées de livres : une ligne, les suivantes masquées (`grid-auto-rows: 0`). `loansTabNext` ouvre un onglet des Prêts, `openCatalog(patch)` un filtre du catalogue.
- Rappels de retour : centrale v4 `libraries.reminder_mode` (manual | auto), `reminder_offset` (jours depuis `due_at`, négatif = avant), `reminder_subject/body` (vide = modèle `REMINDER_DEFAULT` du front) ; bibliothèque v4 `loans.reminded_at`, `reminder_count`. `toRemindSql` (library-api.js) : échéance + offset atteinte et pas relancé depuis, puis tous les 7 jours en retard. `GET /loans?status=remind`, `POST /loans/reminded {ids}`, `summary.toRemind/reminder`. Front : `sendReminder` (mailto puis confirmation), `loanCache`, onglet « À relancer » groupé par emprunteur.
- Accessibilité (app.js) : gestion globale des `.modal-backdrop` (observateur : focus, Échap → `[data-close]`, Tab contenu, focus rendu), `announcePage` après chaque route (titre, focus sur `#view`), `aria-current` dans la nav, classe `.sr-only`, lien d'évitement intercepté (routes en #).
- `lib/stats.js` (stats, confidentialité ; réglages personnels `PUT /stats/prefs` affichés dans « Mon compte » : `prefsHtml` / `bindPrefs`, bibliothèque ouverte avec statistiques), `lib/auth.js` (scrypt, sessions ; `users.role` = `admin` | `user` (compte ordinaire) ; rôle **par bibliothèque** (centrale v7) `user_libraries.role` = `manager` (gestionnaire) / `librarian` (bibliothécaire) / `user` (lecteur, lecture seule) : `roleIn(user, lib)`, `isMember` = compte lié ou admin, `canManage` = membre sauf lecteur (catalogue, prêts, étiquettes, souhaits des membres), `canConfigure` = admin ou gestionnaire (réglages, classement, vidage, codes) ; `spreadRoles` (db.js, à chaque démarrage) reporte un ancien rôle de compte sur ses liens ; `librariesOf` donne le rôle, front `libRole()` et mêmes fonctions, routes `member` / `manage` / `config`, libellés `ROLE_LABELS` / `ROLE_HELP` ; API comptes : `libraries: [{id, role}]`), `lib/invitations.js` (centrale v7 `invitations` : jeton en clair, bibliothèque, rôle, expiration ; `/api/admin/invitations`, et sans connexion `GET|POST /api/invitations/:token` = création du compte ou ajout de la bibliothèque au compte connecté, rôle existant jamais modifié ; front `#/invite/<jeton>` sur l'adresse de la bibliothèque), `lib/isbn.js` (Google Books / BnF SRU / Open Library ; `findIsbn` = ISBN unique par titre + auteur (BnF), `searchEditions` = liste d'éditions pour `GET /isbn-search?title&author|q&bookId` (+ ISBN du fichier epub) ; résumés FR en dernier recours via leslibraires.fr, 1 requête / 3 s — placedeslibraires.fr et Decitre bloquent l'hébergeur), `lib/covers.js` (recherche de couvertures), `lib/media.js`.
- Cookie de session (`setSessionCookie`, auth.js) : en HTTPS `SameSite=None; Secure; Partitioned` pour fonctionner dans un cadre d'un autre site (onglet « Site web » de Teams), `Lax` en HTTP ; l'ancien cookie non partitionné est effacé, `sessionTokens` accepte les deux. CSRF : `jsonOnly`.
- Archives par bibliothèque (`lib/archives.js`, Administration › Sauvegarde) : `GET /api/admin/libraries/:id/archive?db=1&ebooks=1&covers=1` → `mylittlelibrary-<nom>.zip` (`library.db`, `ebooks/`, `media/`, `manifest.json` : réglages de `libraries`, membres, prefs, comptes cités id → identifiant). Restauration en deux temps : `POST /api/admin/archives` (zip brut, 1 Go, exception `jsonOnly`) → jeton + bibliothèque du même nom (casse ignorée), puis `POST /api/admin/archives/:token/apply {overwrite}` (remplace seulement les éléments présents, copie de sécurité de la base, `library_id` réécrit, comptes remappés par identifiant sinon retirés). Rappel mensuel : `backupReminder` de `/api/auth/status` (réglages `backupDoneMonth` / `backupSkippedMonth`), « Reporter » = `sessionStorage` `mll-backup-snooze` (effacé à la connexion).
- Réglages globaux : table `settings` (clé/valeur, `getSetting`/`setSetting` dans db.js). Clé Google Books : `googleBooksKey()` = réglage `googleBooksApiKey` (Administration › Google Books), sinon `GOOGLE_BOOKS_API_KEY`.
- Interface : palette et composants dans `style.css` (variables `:root`, teintes `--sun/--coral/--sky/--grape/--rose` + `-soft`), police Nunito (Google Fonts). Textes d'aide : jamais de paragraphe explicatif, utiliser `hint(texte)` (icône « ? » + info-bulle, section Utilitaires) et des libellés courts. Smartphone : pas de long libellé sur un bouton, `iconText(icone, texte)` = icône seule sous 760 px (avec `title` / `aria-label`), classes `hide-mobile` / `.btn-row.only-mobile`, ou libellé court : `<span class="hide-mobile">long</span><span class="show-mobile">court</span>`. Icones SVG inline : section `Icones` de app.js (`icon(nom)`, `PAGE_COLORS`, `decorateTitle` ajoute la pastille des h1 selon l'adresse).
- `public/app.js` : SPA (routes en hash), sections repérables par `// ================= <Section> =================`. `public/embed.js` : widget catalogue WordPress (Shadow DOM). `wordpress/…/mylittlelibrary-catalogue.php` : plugin shortcode `[bibliotheque …]`.
- `data/` (non versionné) : `central.db`, `libraries/<id>/{library.db, media/, ebooks/, backups/}`, `wishes/` (images des souhaits), `backups/`. Images servies sur `/<slug>/media/` (plus de `/media` global ; `libraryInfo.logoUrl` = `<slug>/media/…`). Sauvegarde admin = zip des bases (`backupTo`).

## Modèle (points non évidents)
- Multi-bibliothèques : tout est filtré par `library_id` ; URL de bibliothèque = slug fixé à la création.
- `copies.format` = `physical` | `ebook` : l'exemplaire numérique n'a **pas de code, d'étiquette ni de prêt** (un seul par livre). `books.format` n'est plus utilisé.
- Fichier epub (v16, `lib/ebooks.js`) : sur l'exemplaire numérique, `file_key` (fichier dans `data/libraries/<id>/ebooks/`, jamais servi en statique), `file_name`, `file_size`. Droits **par bibliothèque** (v17) `libraries.ebook_visible` / `ebook_read` / `ebook_download` = `public` | `members` (`isMember`, lecteurs compris) | `managers` (`canManage`) | `admin` (lire ou télécharger rend visible ; `ebooks.rights(lib, user)`) ; les colonnes `copies.file_visible/read/download` ne servent plus. Import de plusieurs epub : `POST /import/epub` (brut, une requête par fichier ; `lib/epub-meta.js` lit titre, auteurs, résumé, ISBN (OPF, sinon texte du début et de la fin du livre, ISBN papier préféré : `isbnFromText`, `readEpubIsbn`), série, couverture ; fiche existante = même ISBN ou même titre + auteur → fichier ajouté s'il manque). Envoi brut `PUT /copies/:id/file` (application/epub+zip, en-tête `X-File-Name`, 100 Mo, exceptions dans `jsonOnly` de server.js avec `/import/epub` et `/kobo/scan`) ; accès `GET /public/books/:id/epub[?download=1]` ; `book.ebookFile` = droits du visiteur. Liseuse `#/read/:id` (epub.js + JSZip servis sur `/vendor/`). Fichiers orphelins supprimés par `ebooks.purgeOrphans(libId)` après chaque suppression.
- Livre : `collection` (éditeur) distincte de `series` + `series_number` (tome). `collection_number` n'est plus utilisé.
- Statuts de lecture par compte (`book_user_status`) : to_read / reading / read / abandoned + liked / disliked + `rating` (1-5, v19 ; conservée si absente du PUT), avec dates. Filtre catalogue `rating=n` (n étoiles et plus) | `none`.
- Lecteurs (`book_readers`, v15) : comptes membres liés à un livre, indépendants du statut (jamais retirés par un changement de statut). Fiche : bouton « Intéressé » (soi-même, `POST/DELETE /books/:id/readers`) ; autres membres via le formulaire « Modifier » (`readers` de `PUT /books/:id` remplace la liste). Filtres catalogue `mine` (Mes livres) et `reader`. Ajout d'un livre et import : le créateur par défaut, ou `readers` (identifiants, ou noms séparés par des virgules pour la colonne « Lecteurs »). En mise à jour par import, seule la colonne compte. Membres : `libraryMembers` (library-api.js). Les emprunteurs sont des personnes extérieures sans compte.
- Tags = vrais tags (thèmes libres). En v15, les tags qui portaient le nom d'un compte ont été convertis en lecteurs.
- Fiches incomplètes : `MISSING` (library-api.js, conditions SQL par champ) → `GET /books/missing` (comptes), filtre `missing=` de `/books` et de `/export/inventory.*`.
- Prêts : `loans.due_at` ('YYYY-MM-DD', bibliothèque v2 ; défaut `libraries.loan_days`, centrale v3, 0 = aucune ; `dueDate()`, retard = `OVERDUE` en SQL, `GET /loans/summary`, `PUT /loans/:id {dueAt}`). Réservations (`reservations`, bibliothèque v3 : au nom d'un emprunteur `borrower_id`, `created_by` = compte qui l'a saisie ; `resolveBorrower` commun avec le prêt, qui retire la réservation de l'emprunteur ; `reservationsFor` dans `bookDetail` et la réponse du retour). Front : `openCopy` (retour express si prêté), `returnLoan` (alerte réservation), `loanFor` (emprunteur choisi depuis sa fiche, oublié en quittant `/c/` et sa fiche), `pendingAddIsbn`, `refreshLoanBadge`.
- Import `onDuplicate` : `copy` | `skip` | `new` | `update` (`updateFromImport` : colonnes non vides écrasent la fiche, repérée par `bookId` = colonne « ID fiche » de l'export, sinon ISBN).
- Auteurs, séries, éditeurs, collections : pas de table, valeurs libres des fiches (auteurs séparés par des virgules). Gestion via `/values/:kind` (`VALUE_FIELDS`, `rewriteValues`, casse ignorée) ; front : `categoryManager` (`TERM_KINDS`, `free`), onglets « Classement » des réglages.
- Liseuses Kobo (v17, `lib/kobo.js`, option `enable_kobo`, exige `enable_ebooks`) : le navigateur lit la Kobo branchée (Chrome : `showDirectoryPicker` en lecture/écriture ; Firefox : `webkitdirectory`, lecture seule + avertissement) et envoie `.kobo/KoboReader.sqlite` brut à `POST /kobo/scan` (en-tête `X-Kobo-Version` = `.kobo/version`), lu par `node:sqlite` (livres `ContentType = 6`, `file://` seulement). Tables `kobo_devices` (numéro de série, propriétaire `user_id`) et `kobo_items` (livres du dernier scan ; `book_id`, `manual` = rattachement manuel conservé, `last_derived` = statut déduit au scan précédent, appliqué seulement s'il change, jamais de rétrogradation d'un « Lu » ; abandonné = progression inchangée depuis `user_library_prefs.stale_days` et au moins 5 % lus, sinon ignoré comme ouvert par erreur). Rapprochement : repère `[mll-<id>]` dans le chemin, ISBN, titre + nom de l'auteur. Envoi : `GET /kobo/books/:id/epub` (droit de téléchargement) réécrit l'OPF (titre, auteurs, ISBN, `calibre:series` + EPUB 3 `belongs-to-collection`) et donne le chemin `Bibliotheque/<Série>/<NN> - <Titre> [mll-id].epub` (en-tête `X-Kobo-Path`). Envoi depuis l'appli (Chrome) : `POST /kobo/devices/:id/pushed` crée une ligne `pending` (v18) gardée jusqu'à ce qu'un scan retrouve le livre (30 jours max). Front : liseuse branchée = variable `kobo` (session de la page ; `kobo.device` après scan ; `koboOn()`), branchement par le menu du compte (« Brancher une liseuse », « Toutes les liseuses ») ; Chrome : dossier mémorisé en IndexedDB (`mll-kobo`, par bibliothèque), reconnexion seule si l'autorisation est gardée sinon « Reconnecter » (un clic), débranchement détecté toutes les 5 s (`watchKobo`) ; nom par défaut « <modèle> de <compte Kobo> » (`MODELS`, table `user`.UserDisplayName tronqué avant le @, souvent une adresse e-mail), remplace seulement un nom par défaut ; page d'une liseuse filtrable comme le catalogue (`GET /kobo/devices/:id?q&category&series&tag&reading&sort`, recherche seule sur sa ligne en grand écran : classe `filters-search-row`, filtres de fiche via `searchBooks`) ; seulement si branchée : onglet de la liseuse, filtre catalogue `kobo=on|off&koboDevice=` (searchBooks), envoi groupé depuis la sélection (`pushManyToKobo` ; seule action de la sélection pour un lecteur), « Copier les fichiers manquants » sur la page d'une liseuse, « Supprimer de la liseuse » (Chrome : `kobo.remove` efface le fichier et le dossier parent vide, puis `DELETE /kobo/items/:id`), fiche créée depuis une liseuse ouverte avec retour (`koboReturn`).
- Options par bibliothèque : `enable_ebooks`, `enable_kobo`, `enable_reading_status`, `enable_tags`, `enable_stats`, filtres et éléments des miniatures du catalogue (`catalog_filters`, `catalog_card` : JSON, NULL = tous ; statuts en trois filtres `statusUser`/`reading`/`opinion` depuis v15), bouton Scanner de l'en-tête (centrale v2 : `scan_codes` = copy | isbn | both, `scan_action` = loan | book ; `settings.scan`, front `scanAndOpen`, `GET /copies/by-isbn/:isbn` = livres de l'ISBN + exemplaires papier).

## Méthode de travail
- **Avant toute migration** : tester sur une copie (copie de `data/central.db` et des `data/libraries/*/library.db` par `VACUUM INTO` vers un dossier temporaire, instance de test `MLL_DATA_DIR=<dossier> PORT=3100 node server.js`, compte jetable via `node scripts/set-password.js`), puis sauvegarder les vraies bases dans `data/backups/` (ex. `central-avant-vNN.db`) ou `data/libraries/<id>/backups/`.
- Tester d'abord par l'API (curl avec corps JSON écrit dans un fichier : les accents passés en argument sous Git Bash sont mal encodés). Vérification visuelle seulement si l'interface change beaucoup.
- Grosses modifications de `app.js` : petits scripts Node de remplacement (texte exact) plutôt que `sed` ; `node --check` après chaque modification.
- Commit + push sur `main` après chaque fonctionnalité validée (dépôt GitHub privé Gatomlo/MyLittleLibraryV2), mettre à jour `README.md` si la fonctionnalité est visible.
- Réponses à l'utilisateur : courtes, en français, avec les instructions de déploiement quand le serveur ou la base changent.
